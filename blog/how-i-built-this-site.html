这个网站是怎么搭起来的

2026年10月7日 · 约 2 分钟
  • 折腾
  • 前端

把过程记下来，免得以后忘了，也给同样想做个人网站的人一个参考。

整体流程

本地写文件 → 推到 GitHub 仓库 → Cloudflare Pages 自动构建 → 得到网址 → 绑定自己的域名。

只有第一次配置麻烦一点，之后更新网站只剩一条推送操作。

为什么不用服务器

静态站点不需要后端，所有的页面在发布时就生成好了，托管平台直接分发文件。 好处很直接：

  • 不用交服务器租金，个人站点免费额度完全够用
  • 不用管系统更新、安全补丁、被扫端口这些事
  • 自带 HTTPS 证书，全球有加速节点

等到需要用户登录、评论、数据库的时候，再考虑上服务器也不迟。

发布配置

Cloudflare Pages 上只需要填三个字段：

设置项 值
Framework preset None
Build command 留空
Build output directory /

因为这个站点是纯 HTML、CSS、JavaScript，没有构建步骤，平台把整个文件夹当成成品直接发出去。

写文章的方式

博客用 Markdown 写，放在 posts/ 目录里，运行一条命令生成页面：

npm run blog

它会扫描 posts/ 下所有 .md 文件，按日期从新到旧排好，生成文章列表和每篇文章的 HTML。 生成出来的 blog.html 和 blog/ 目录照样提交上去，所以线上依然不需要构建。

代码块这类内容在 Markdown 里写起来很舒服：

int main() {
    // 不用担心 < > 符号需要转义
    std::vector<int> v{1, 2, 3};
    return 0;
}

踩过的坑

图片文件名的大小写在本地无所谓，但服务器是 Linux，区分大小写。 Photo.JPG 和 photo.jpg 会被当成两个文件，页面上就是一个裂开的图标。

统一用小写文件名，能省掉以后很多莫名其妙的排查。

暂时就这些，有新问题再补。
